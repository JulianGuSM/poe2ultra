# poe2ultra：攻略全文翻译

这是以 poe2perfect 为基础，接入你现有 poe2translator 翻译逻辑的本地 Chrome 扩展。原来的 poe2translator 目录没有修改。

## 安装与使用

1. 打开 Chrome 的 `chrome://extensions`，开启开发者模式。
2. 点击 **加载未打包的扩展程序**，选择本项目的 **`.output/chrome-mv3`** 目录，所选文件夹内应直接包含 `manifest.json`。此前所说的“加载已解压的扩展程序”指的就是这个操作。若使用扩展 ZIP 包，先解压；若只有源码，先按 [README 的开发说明](../README.md#开发)构建。
3. 在 Mobalytics 上使用时，先停用原版 poe2perfect，避免两份扩展同时接管同一页面。1.4.0 已包含原 poe2translator 的划词功能，建议停用旧划词插件，避免浮标和 Alt+Q 冲突。
4. 点击攻略导航栏右侧的环形翻译进度，再点击详情框中的 **翻译设置**；也可以点击 poe2ultra 的工具栏图标。在 **API 密钥** 中填写 Key，点击 **保存设置**。已有 poe2ultra 设置保留；旧 poe2translator 的运行时设置由 Chrome 隔离，不能自动读取，需要手动复制过来。
5. 打开或刷新 POE2 攻略页面，点击环形进度，在详情框中点击 **开始翻译 · 简中 + 繁中**。
6. 原文始终保留，导航栏右侧的 **Original / 简中 / 繁中** 三段切换按钮选择显示语言。简中、繁中译文在每个文本块下方显示，Original 隐藏译文。首次按批次生成两套独立译文，后续读取缓存；语言切换不调用 API。

环形进度和语言切换位于导航栏右侧、折叠及退出按钮左边，与攻略标签分开。点击圆环查看缓存文字块和费用、翻译状态及操作；点击 X、按 Esc 或点击外部关闭。按每次模型响应记录这篇攻略的估算费用（包括格式无效但返回了用量的响应），刷新后仍能查看，JSON 备份会携带费用记录；旧版没有留下的费用无法追溯。清空攻略译文不会清除费用记录。

导航标签与技能、装备、天赋提示框中由扩展生成的固定标题使用内置简中/繁中界面文案，不等待攻略翻译缓存，也不发送给 DeepSeek。例如“Progression”显示为“升级路线 / 升級路線”，“Additional Effects From Quality”显示为“品质附加效果 / 品質附加效果”。点击展开的提示框对缓存译文使用较亮的浅灰色。

### 点了简中/繁中，为什么正文还是英文？

语言按钮只切换已经缓存的译文。第一次使用时还没有译文，需要点击环形进度，再在详情框中点击橙色的 **开始翻译 · 简中 + 繁中**。`已缓存 0 / 2,249 个文字块` 表示提取出 2,249 个去重后的段落或名称、说明等文字块，尚未缓存任何块的两套译文；它不是 API 请求次数。待翻译字符数统计剩余原文长度，不是 token 数。

更新时将新文件放在原安装目录，在 `chrome://extensions` 的现有 poe2ultra 卡片上点击圆形箭头 **↻（重新加载）**，再刷新攻略页面即可；不必卸载重装或再次添加扩展。完整的首次安装和更新步骤见 [README](../README.md#安装与使用)。

本版支持 Responses API 和 Chat Completions，也已接入原插件的自定义接口、额外请求头/请求体、术语库导入和费用单价设置。自定义接口需在设置页点击 **保存设置** 授权对应域名；自动保存不会弹出授权。设置页的“测试连接”会发送样本文本并可能计费，不会自动执行。

### 原插件的设置与划词翻译

设置页复用了 poe2translator 的中文界面和配置项：接口与模型、思考模式、流式输出、输出上限、超时、提示词、划词与面板、术语表与联网补充、费用估算。修改后会自动保存；高级 JSON 填写错误时会显示未保存状态。

在普通 HTTP/HTTPS 网页的主页面，或 poe2ultra 的攻略正文中选中文字，点击翻译浮标、按 **Alt+Q**，或使用右键菜单 **翻译选中文本（DeepSeek）**。结果面板保留原文、简繁分栏及分别复制、停止、重试、术语来源、提示词、用时和费用显示；可在 **划词与面板** 中配置自动翻译、主题、宽度等。自动划词翻译默认关闭。Chrome 内部页面、扩展商店和内置 PDF 等受限页面不支持。

快捷键冲突可到 `chrome://extensions/shortcuts` 调整。升级后先重新加载扩展，再刷新已打开的网页；Chrome 如提示新增网站访问权限，检查并启用扩展。原插件目录未修改。

攻略始终生成独立的简中和繁中两套译文；**目标语言** 和 **划词翻译同时输出简中 + 繁中两个版本** 只控制划词。划词保留原插件的即时请求行为，长期双语缓存用于攻略全文翻译。划词面板显示本次费用，攻略进度详情框显示本轮和累计费用估算；内置单价不会自动更新，也可填写自定义单价。

攻略请求固定使用双语 JSON 协议，额外请求体不能覆盖 `messages`、`input`、`instructions`、`text` 或 `response_format`；这些字段在划词时仍按原插件行为覆盖。设置页的系统/用户提示词仅用于划词，划词用户提示词中缺少 `{{text}}` 时会自动追加原文。

### JSON 格式错误

旧错误“模型返回的 JSON 格式无效，本批未缓存”只说明返回内容不能解析，未保存具体返回，因此不能仅凭这一句确定是截断还是模型输出了其他格式。

攻略请求使用接口级 JSON 模式：Chat Completions 使用 `response_format`，Responses 使用 `text.format`；1.5.1 将返回结构作为 user 数据中的 `output_format` 提供，不向系统提示词追加格式指令。完整 JSON 外多了说明或代码块时可以提取，只检查块编号和两套非空译文，不要求格式片段对齐、不校验数字。不会凭空补齐缺失译文，也不会修造损坏 JSON。

若仍失败，界面会显示空内容、未闭合或语法错误、接收字符数及返回开头/结尾；接口明确返回输出上限时，会提示调高 **最大输出 token** 或关闭思考。之前缓存仍保留，点击继续只处理缺失内容，不会自动重复收费请求。

参数依据：[DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[Responses 输出格式](https://api-docs.deepseek.com/api/create-response/)。

### 翻译进度与整块翻译

点击开始后，环形进度显示已缓存百分比；点开详情框可查看文字块数、当前批次、处理阶段、总用时和当前阶段用时。阶段包括检查缓存、排队、匹配术语、准备术语上下文、等待 DeepSeek、接收译文、校验及保存。已接收字符数来自当前请求的实际流式输出（含 JSON 格式字符），不是 token 数或已完成文字块数。

百分比按当前攻略已经保存了两套译文的文字块数计算，包含已有缓存；批次数只统计本次需要处理的缺失内容。每批校验并保存后才增加百分比，第一批完成前可能一直是 0%。用时表示经过的时间，不保证网络正在传输，也不是预计剩余时间。

详情框会按每次模型响应返回的 token 用量和当时设置的单价分别显示本轮与本篇攻略累计人民币估算。若某次模型输出无效但接口仍返回用量，该次也计入估算；没有用量时会标注无法估算或只有部分请求可估算。已缓存文字块和本地术语命中不发模型请求。累计记录从 1.6.6 开始保存，旧版费用无法回溯；实际费用以服务商账单为准。

Debug 仅决定是否记录详细输入输出，不决定是否可以继续。单批 JSON 格式错误、缺失译文等输出问题会使该批保持未缓存，并继续后续批次；本轮结束后可点 **继续翻译剩余内容** 重试。连续 3 批输出错误会暂停，避免在系统性错误下持续付费。鉴权、网络和存储错误会直接暂停；修复后同样可点继续，已缓存部分不会重译。

1.5.0 已按需求移除数字保护标记及位置/数量校验。每个文字块的原文直接交给 DeepSeek，返回两份完整译文后缓存，单独显示在原文下方。原文中的加粗、链接、技能标签保留原样，不再往这些片段里填译文。

### 两套独立提示词

全文提示词集中在 [`src/lib/translation/guide-prompt.js`](../src/lib/translation/guide-prompt.js)。系统提示词仅使用指定的 POE2 本地化专家文本：理解游戏机制、忠实翻译、两地独立术语、版本号和数值单位。Chat 的 system 消息与 Responses 的 instructions 都直接使用这份文本，不追加其他规则。每批原文、cn/tw 术语、poe2db 来源和 JSON 返回结构单独放在 user 数据中。

版本号按语境解释：谈论更新/加强时，`in 0.5` 表达“在 0.5 版本中”；秒数、倍率则按原文单位理解。`6K`、百分比和区间保留原数值写法。相邻富文本片段合成完整段落后再发送，译文按自然中文语序组织，无需保持片段顺序。

划词提示词集中在 [`src/lib/selection/prompt.js`](../src/lib/selection/prompt.js)，包括默认系统/用户模板、双语输出规则、术语规则与上下文合成。设置页 **2 · 划词翻译提示词** 只控制这一路，不影响全文翻译。

已有付费缓存保留，后续缺失内容使用新的全文提示词。程序只检查可读取的输出、块对应关系和非空译文，术语和译文质量仍取决于模型与可用来源。

## 翻译范围

包括攻略标题、正文、优缺点、所有构筑阶段的说明、装备词缀、技能说明、重点天赋与扩展自己的提示框。当前未打开的标签页、阶段也会纳入计划。

不包括网站导航、广告、评论、作者身份、无关 UI，以及网站自身绘制的天赋树/异界树画布和原生悬浮框。功能按钮等固定界面文案保留英文。技能复制保留英文名称，方便游戏中搜索；对应中文显示在名称下方。

正文按段落提取，同一段内加粗、链接和技能标签的文字合成一段，送给模型的是 `{id, text}`。返回 `{id, cn, tw}`，两种译文各为完整字符串。原文保持不变，译文在段落、标题、列表项及名称/说明下方用淡灰色显示。只为映射批次结果保留 ID，不再要求对齐格式片段。译文作为纯文本渲染，不执行模型返回的 HTML。

## 复用的翻译逻辑

`src/lib/translation/vendor/` 保留原插件的 DeepSeek 客户端、流式解析、术语抽取、poe2db 直查和 Tavily 检索模块。提示词移至上述两个独立文件；`protocol.ts` 只负责返回数据解析等协议逻辑，`vendor/defaults.js` 只引用划词默认模板，不存放提示词文本。术语采集仍由 `src/lib/translation/context.js` 负责，它只返回数据，不拼接提示词。

- 保留 4,324 条本地术语，简中和繁中分别取各自一列。
- 完整命中的独立名称直接使用本地两套译名，不调用模型。
- 其余内容每批请求一次，同时返回两套独立译文。共用输入与检索上下文，但两份译文都会产生输出 token。
- 默认启用本地术语及 poe2db 直查；Tavily 默认关闭，可填写 Key 后开启。
- 默认关闭模型思考，避免全文翻译额外消耗推理 token。
- 全文返回带段落 ID 的双语 JSON，由适配层验证。划词使用原插件的双标签格式，规则在独立的划词提示词文件中。

## 缓存如何省钱

数据保存在**扩展自己的 IndexedDB**，不保存在 Mobalytics 的数据库，也不同步到云端。每个条目同时含 `cn`、`tw` 两组译文，写入事务完成后才报告成功。没有时间过期和自动清理。

缓存按原文内容寻址，记录键为：

`sourceHash = SHA-256(文字块原文)`

每条新记录另存 `configHash`，用于标记生成译文时的翻译配置。它包含模型、提示词、术语表内容和会影响译文的参数，不包含 API Key、页面 URL、当前显示语言、主题、面板宽度或费用单价。读取时只要原文哈希命中就显示已有译文；配置哈希不同时仍优先显示旧译文，不会自动调用模型或覆盖记录。手动重译才会用当前配置生成并覆盖该文字块的译文。每个原文哈希当前只保留一版译文。旧缓存会优先按已保存的原文迁移；没有原文且旧配置版本也无法重建的记录无法自动迁移。

- 刷新、重开、重启浏览器：原文相同就读取缓存；配置不同仍显示旧译文。
- 简中与繁中切换：同一条缓存取不同字段，不重新翻译。
- 同一文字在多个阶段或不同攻略中重复：复用同一条缓存。
- 攻略更新：原文发生变化的段落重新翻译，其余照用。
- 中断或失败：已经保存的批次保留，下次只补缺失内容；不会自动反复重试收费请求。
- 同一配置下多标签页同时翻译：付费工作排队，实际请求前再次检查缓存，避免重复收费。
- 更改模型或术语策略：已有译文继续显示，不自动重翻；手动重译会用当前设置覆盖该文字块缓存。
- 更改划词提示词：不影响全文请求和已有全文缓存。
- 导入不同术语表：已有译文继续显示，不自动重翻；手动重译才采用新表。正在运行的攻略任务保持启动时的术语表，避免同一任务混用两份词库。
- 关闭标签页或点击 **停止翻译**：停止后续工作并取消当前请求；服务商可能仍对已经处理的请求计费。

卸载扩展、清除扩展数据或换浏览器配置文件会丢失本地缓存。可在设置页 **攻略全文翻译与缓存** 导出 JSON 备份；重新安装后选择该文件，检查条目数并点击 **合并并恢复翻译参数**。备份包含简中和繁中译文、1.6.6 起积累的费用估算记录、匹配旧缓存所需的翻译参数及导入术语表，不自动加入 API Key 或额外请求头。导入会保留当前同键译文，按记录编号合并费用，避免重复计入，并恢复备份中的翻译参数。API Key 要重新填写，刷新攻略即可读取已备份的译文和费用。自定义请求体与译文本身可能包含个人内容，请自行保管备份文件。

1.6.2 起，同一区域可点击 **导出累计译文（CSV）**，下载本地攻略缓存与成功完成的双语划词结果。CSV 固定为 **英语原文、简中、繁中** 三列；逗号、引号与换行按 CSV 规则转义，UTF-8 文件带 BOM，便于 Excel 显示中文。同一组三语内容只导出一行，不同译法分别保留。新版攻略缓存同时记录明文原文；旧缓存只有不可逆的哈希键，重新打开对应攻略时才会补记原文，无需付费重译。尚未补记的旧条目暂不出现在 CSV 中，导出后会提示数量。划词必须成功拆出完整双语结果才入表；单语模式仍可使用，但无法组成双语行。CSV 不含 API Key、请求头或设置，也不能作为缓存导入；重装恢复攻略缓存请用 JSON。每次 CSV 下载是完整快照，扩展不会自动改写电脑上的既有文件。

## “沉浸式全文翻译”通常怎么实现

通常由 Chrome content script 读取网页 DOM，找出需要翻译的文本块，排除脚本、输入框、代码等，再分批请求翻译服务。拿到结果后，将译文插入原段落旁边或替换其文字。对滚动加载/动态页面，还要观察后续 DOM 变化，避免漏掉新段落和重复翻译。

通用扩展很难精确知道哪些文字是你关心的攻略内容，导航和按钮也可能被识别为正文。这里可以省去猜测：poe2perfect 已经将网页提取为结构化 Build 数据，我们直接翻译这份数据里的展示字段。页面有多少无关 UI 都不会影响送给模型的内容。

这里不是保存一整份静态网页快照，而是保存段落译文。下一次用最新攻略结构和已保存的译文重新渲染，因此能保留交互，同时只为变化的内容付费。

## Debug 日志

1.4.2 在设置页增加 **6 · Debug 日志**。开启并保存后，下一次开始/继续全文翻译会记录每批完整输入输出。旧版没有保留的历史失败不能恢复；不需要清缓存，也不会重新请求已缓存块。操作步骤见 [README 的 Debug 说明](../README.md#出错时开启-debug-日志)。

1.5.0 不再因格式片段的合并、拆分或数字位置变化而报错。Debug 继续记录每批完整请求与返回；原先的 `spanCount`、数字保护数据已不再产生。缺少整块译文时会报告块编号和语言。

每份 JSON 导出中的 `records` 是保留的批次列表，主要字段如下：

| 字段 | 内容 |
| --- | --- |
| `id` / `runId` / `batch` / `batches` | 调试编号、此次运行编号及批次进度 |
| `context` | 攻略地址、模型、API 形态和缓存配置摘要 |
| `data.sourceSegments` / `uncachedSegments` | 此批计划原文及请求前复查缓存后仍缺失的内容 |
| `data.providerInput` | 排除本地术语命中后的模型输入块，`sourcePositions` 映射回未缓存块 |
| `data.modelInput` | 完整文本块、术语上下文及独立生成的全文 system/user 内容 |
| `data.request` | 实际请求的地址、方法、脱敏请求头和最终请求体 |
| `data.http` / `stream.http` | HTTP 状态、脱敏响应头、解码后的响应正文或 SSE；出错或取消时可能为部分内容 |
| `data.response` | 客户端解析后的完整模型正文、思考内容、用量、结束原因等；网络失败时可能不存在 |
| `stream.text` / `stream.reasoning` | 实际收到的流式正文/思考增量；关闭流式时主要看 `data.response` |
| `data.result` / `data.cache` | 按块读取的译文结果、复用及实际写入数量 |
| `events` / `error` | 时间线、经过时间、错误堆栈及结构化校验细节 |

日志在扩展自己的独立 IndexedDB 中保存，刷新网页、关闭设置页和重启后台后仍可读取。最近 500 批以外的旧记录会删除，不截断保留下来的请求或返回。意外关闭时最后记录可能仍标为“进行中 / 上次未正常结束”；已收到的流式内容约每 2 秒保存一次，正常完成、报错、取消时会再保存。突然退出可能丢失最后尚未写入的部分。

数据写入本地和输出控制台之前会脱敏已知 API 密钥、自定义鉴权头和凭据字段。日志仍包含完整正文与自定义提示词，应在分享前查看内容。日志不上传，不额外发起翻译请求，不自动重复失败请求，清空日志不会清除已保存的简繁译文。存储日志失败会提示，但不阻断翻译。
